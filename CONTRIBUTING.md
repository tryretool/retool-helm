# Contributing

## Every chart change

- Bump `version` in [charts/retool/Chart.yaml](charts/retool/Chart.yaml). CI fails on a chart change without a version bump.
- If you touched `charts/retool/values.yaml`, run `charts/retool/schema/generate.sh` and commit the result (see below).
- Add or update a values file in [charts/retool/ci/](charts/retool/ci) when you add an option, so CI renders and installs it.

## Documenting values

[charts/retool/values.yaml](charts/retool/values.yaml) is the single source for three files:

| File | Generated by | From |
|------|--------------|------|
| `charts/retool/README.md` | [helm-docs](https://github.com/norwoodj/helm-docs) | `# --` comments and [README.md.gotmpl](charts/retool/README.md.gotmpl) |
| `charts/retool/values.schema.json` | [helm-values-schema-json](https://github.com/losisin/helm-values-schema-json) | the values themselves, `# @schema` annotations, and `# --` comments as descriptions |
| `values.yaml` (repo root) | a copy | `charts/retool/values.yaml` |

Regenerate all three with:

```bash
charts/retool/schema/generate.sh
```

The script downloads pinned, checksum-verified versions of both tools into `charts/retool/schema/.bin`. CI runs `generate.sh --check` and fails if the committed files are out of date.

Helm validates every install, upgrade, `template` and `lint` against `values.schema.json`, so a wrong type in the schema breaks real deployments. Read the conventions below before adding annotations.

### Conventions

**Every key gets a `# --` description** directly above it: one or two sentences, in sentence case, ending with a period. Mention what the key does, not how the template implements it. Wrap other key names in backticks.

```yaml
# @schema type: [integer, string]; pattern: ^[0-9]+$
# -- Number of backend replicas. With more than 1, a separate jobs-runner pod is also deployed.
replicaCount: 2
```

**Every documented key declares its type with `# @schema type:`**, including keys that use `$ref:`. Don't rely on the schema tool inferring a type from the default value: the type then changes whenever someone edits the default, and it's usually narrower than what the templates accept. `generate.sh` fails if a key with a `# --` description has no explicit type. A `$ref:` doesn't count, because the generator still infers a type from the default and requires both. Keys inside a top-level `# @schema hidden` section are exempt until that section is converted.

**Put `# @schema` lines above the `# --` line.** helm-docs reads everything from `# --` down to the key as the description, so an annotation below it would leak into the README.

```yaml
# @schema type: string; enum: [Always, IfNotPresent, Never]
# -- Image pull policy for Retool containers.
pullPolicy: "IfNotPresent"
```

**Optional keys are real keys with an empty value, never commented out.** Neither tool sees commented-out keys, so they would be missing from the README and the schema. An empty value is `null`, which templates treat the same as a missing key. Don't use `""` instead: `quote` renders `null` and `""` differently, so the rendered manifests would change. Include `null` in their type, and add a helm-docs type hint in parentheses, since helm-docs can't tell the type from an empty value:

```yaml
# @schema type: [string, null]
# -- (string) Name of an existing Secret holding the license key. Use instead of `config.licenseKey`.
licenseKeySecretName:
```

**Give a key every type the templates accept.** Check how the value is used before choosing its type:

- Numbers rendered into a manifest work as an integer or a numeric string (`replicaCount: "2"` renders as `replicas: 2`), so accept both and reject anything else: `# @schema type: [integer, string]; pattern: ^[0-9]+$`. JSON Schema applies `pattern` only to strings.
- Booleans rendered with `quote` (usually into an env var) work as a boolean or the strings `"true"`/`"false"`: `# @schema type: [boolean, string]; enum: [true, false, "true", "false"]`. Don't do this for switches the templates test with `if`, where the string `"false"` counts as true.
- Resource requests and limits go through the shared definition, with the defaults hidden so they don't become the schema:

  ```yaml
  # @schema type: object; $ref: schema/definitions.json#/definitions/resources
  # -- Resources for the backend.
  resources:
    # @schema hidden
    limits:
      cpu: 4096m
  ```

  Shared definitions live in [schema/definitions.json](charts/retool/schema/definitions.json) and are bundled into `values.schema.json`.
- Free-form Kubernetes structures (affinity, security contexts, `extraManifests`) should stay open objects or arrays. Hide example contents with `# @schema hidden` rather than letting the defaults become the schema.

**Use `enum` only for values Kubernetes or Retool would reject anyway**, such as `service.type` or `pullPolicy`.

**Mark values the chart cannot work without as required in three places.** Helm validates the merged values, where the default always supplies the key, so `required` alone never fails in Helm; it makes editors flag a values file that omits the key. `minLength: 1` is what makes Helm reject the empty default. Add `required` to each parent too, so editors flag the key when its parent section is missing. Keep the template's `required` call as well, since Helm 3.16+ can skip schema validation with `--skip-schema-validation`. Show it in the README with `# @default -- none (required)`:

```yaml
image: # @schema required
  # @schema type: string; required; minLength: 1
  # -- Retool version to deploy, e.g. `3.148.12-stable`. Required: the chart does not pick a version for you.
  # @default -- none (required)
  tag: ""
```

Values that are only required depending on other settings, such as `config.encryptionKey`, stay as `required`/`fail` checks in the templates. A schema can't see whether a Secret already exists in the cluster, and its error messages for conditions that involve other keys are worse.

**Use `# @default --` when the effective default is computed in a template**, so the README shows what actually happens:

```yaml
# @schema type: [string, null]
# -- (string) Key in `config.licenseKeySecretName` holding the license key.
# @default -- `license-key`
licenseKeySecretKey:
```

**Put examples above the `# --` line**, as plain comments. Both tools ignore comments above it, and multi-line YAML would break the README table.

```yaml
# Example:
#   podDisruptionBudget:
#     maxUnavailable: 1
# -- PodDisruptionBudget spec for Retool deployments. Empty creates none.
podDisruptionBudget: {}
```

**Don't set `additionalProperties: false`** for now. Unknown keys are allowed so that existing values files keep working. We'll tighten this section by section in minor releases, with release notes.

### Sections not yet annotated

Top-level sections that haven't been converted yet are marked `# @schema hidden`, which keeps them out of the schema (anything is accepted) and the README. To convert one:

1. Turn every commented-out option into a real key, and give every key a `# --` description and an explicit `# @schema type`.
2. Read the templates that consume the section and set types per the conventions above.
3. Remove the `# @schema hidden` marker and run `generate.sh`.
4. Run `charts/retool/schema/compare-render.sh`. It renders the same combinations as CI (every `ci/` values file alone and with each option file) on the commit your branch started from (its merge base with `origin/main`) and on your working tree; documentation changes must report every combination as `same`.
5. Check that the CI values files and the repo-root `values.yaml` from `main` still pass validation (`helm lint charts/retool -f <file>`).
